# Отчёт T002

## План до кода

**Цель:** создать единый runtime-контракт и проверяемую загрузку локального
контента для level meta, balance, incidents, radio, theme и Tiled map.

**Контекст:** `AGENTS.md`, `.agents/skills/moon-courier-sdd/SKILL.md`,
`tasks/T002-content-contracts.md`, `features/F002-content-contracts.md`,
`specs/technical/05-map-tiled.md`, `specs/technical/06-map-validation.md`,
`specs/technical/07-contracts.md`, `contracts/tiled-layer-contract.md`,
`contracts/*.schema.json`, `contracts/examples/*`.

### Spec-audit

| T002-R1 | Каждый contract example проходит соответствующую Zod/Tiled-схему                | unit test + CLI                 |
| T002-R2 | Ошибка имеет стабильный code и точный JSON path                                 | негативные schema/map fixtures  |

Реальных противоречий в нормативных документах нет. Примеры level meta и
minimal map демонстрационные и не образуют один связанный level bundle:
их самостоятельная валидность проверяется CLI, а cross-document правила —
отдельным согласованным fixture-набором. Минимальный пример не считается
финальной картой, поэтому правило размера hazard-zone для уровней 2–4 будет
проверяться при добавлении этих карт, а не искусственно применяться к нему.

## Результат

T002 выполнена. Добавлены runtime Zod-схемы и типы для пяти JSON-контрактов,
парсер/loader с единым `ContentValidationError`, bundle-level references и
Tiled validator структуры, properties, объектов, сетки, BFS, risk-choice и
hazard-зон. CLI теперь фактически проверяет все шесть файлов
`contracts/examples` теми же public loaders, которые предназначены runtime.

## Три прохода

### 1. Соответствие спецификации

Для каждого критерия создано исполнимое доказательство. Все contract examples
загружаются; negative fixtures проверяют exact paths/codes, Tiled structure,
references, blocked/reachability, risk-choice и zone design. Целевые тесты и
CLI зелёные.

### 2. Простота и границы

Два независимых read-only review выявили и помогли закрыть реальные дефекты:
обход forbidden properties/scripts, URI schemes, invalid JSON paths, missing
decoration checks, profile identity, blocked hazard counting и polygon payload.
Внутренний schema barrel удалён; зона имеет одну public entry point. BFS и
content logic не зависят от React, Phaser, Zustand, DOM или timers.

### 3. Регрессия и пользовательский сценарий

После всех исправлений полный immutable `verify` image прошёл 55 тестов и
production build. Existing Playwright mouse/canvas scenario повторно прошёл
против healthy Vite без console/network/layout ошибок. README и CODEMAP
сверены с реализацией.

## Допущения

- `level-02-shackleton.json` и `minimal-map.tmj` — независимые contract
  examples, а не один bundle; cross-file validation доказана согласованным
  fixture.
- Zone-size design не применяется к standalone minimal-map. Для финальной
  карты loader получает `levelOrdinal`, что включает 8–30 и 20+ правила.
- Balance document не содержит собственного ID, поэтому identity передаётся
  bundle loader отдельным `balanceProfileId` и сверяется с level meta.

## Зависимости и лицензии

Новых пакетов нет. Использован уже разрешённый и закреплённый `zod@4.4.3`
(MIT). Lockfile не менялся; ассеты не добавлялись.

## Остаточные риски

- CLI пока проверяет предоставленные examples по отдельным документам, потому
  что пакет не содержит согласованный runtime level directory. Реальные
  level bundles появятся в последующих задачах и будут проходить
  `loadContentBundle` с zone-design validation.
- Как и после T001, Vite сообщает о Phaser chunk около 1.57 MB; T002 его не
  увеличила и performance-оптимизация не входит в scope.
