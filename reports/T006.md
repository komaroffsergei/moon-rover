Обнаруженный contract gap: T005 runtime-клетка содержала только chance и теряла
incident weights/profile; normal weights не имели нормативного источника, а
schema допускала пустой/zero-sum набор. Минимальное решение — существующий
incidents document получает обязательный профиль `normal`, положительную сумму
weights и валидируемые `dustStormGameMinutes=10`/
`selfRepairGameMinutes=10`. Hazard сохраняет связанный `hazardProfileId`, normal
chance сверяется с balance, а cooldown берётся из `balance.routing`.

Локальные допущения: triggering cell не входит в cooldown; event roll выполняется
после списания батареи по заданному technical order, поэтому active incident
временно имеет приоритет над OUT_OF_BATTERY. После его разрешения нулевая батарея
останавливает rover. Если final cell вызвала incident, прибытие завершается после
разрешения incident. Route с недостаточной батареей разрешён: rover завершает
текущий вход, battery становится 0, последующие клетки не исполняются.

### Риски

- RNG draw на tick вместо entry разрушит chunk determinism — независимые
  per-rover streams и forced-chance tests фиксируют правило.
- Таймер и segment могут дважды потребить один fixed-step — используется единый
  game-minute budget с переносом только остатка.
- Incident и battery=0 конкурируют за status — active incident хранится отдельно,
  а итоговый status выводится в нормативном порядке.

## Результат

Подтверждённые маршруты теперь исполняются внутри существующего fixed-step
движка: logical cell меняется только при завершении входа, snapshot отдаёт
интерполяционный `movement.progress`, а батарея списывается общей функцией ровно
один раз на destination cell. Нулевая батарея сохраняет незавершённый маршрут и
останавливает дальнейшее движение.

Для каждого rover созданы два независимых pure-rand stream: trigger и выбор
вида incident. Клетка ссылается на runtime incident profile, normal/hazard
chance и weights приходят из валидированного content bundle. Реализованы
DELAYED, BROKEN, STUCK, SELF_REPAIR, числовые таймеры, cooldown на три успешных
входа и отложенное прибытие. Active incident нельзя обойти переназначением
маршрута, разгрузкой или зарядкой до `INCIDENT_RESOLVED`/`ROVER_ARRIVED`.

## Допущения

- Triggering cell не входит в cooldown: пропускаются следующие три завершённых
  входа, четвёртый снова eligible.
- Если battery обнулилась на triggering cell, incident имеет временный приоритет;
  после его разрешения final arrival фиксируется, затем rover получает
  `OUT_OF_BATTERY`. На промежуточной клетке маршрут сохраняется остановленным.
- Route с недостаточным forecast battery разрешён: текущий вход завершается и
  clamp до нуля предотвращает только следующие входы.

## Зависимости и лицензии

Новых зависимостей и ассетов нет. Использована уже зафиксированная `pure-rand`.

## Остаточные риски

JSON Schema стандартными средствами проверяет exact duplicate profile objects,
но не уникальность произвольного поля `id` у различающихся объектов; canonical
Zod loader дополнительно и обязательно отклоняет любые повторные ID. Production
build остаётся зелёным с прежним предупреждением Vite о Phaser chunk 1,566.36 kB
(gzip 417.81 kB); T006 новых UI/dependency chunks не добавляет.
