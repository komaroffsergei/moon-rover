# Отчёт T011

## План до кода

**Цель:** подготовить production-каталог из четырёх статических Tiled-уровней с
проверяемым выбором риска, нарастающей сложностью, фиксированно проходимыми
smoke-сценариями и локальными ассетами в заданных бюджетах.

**Контекст:** `AGENTS.md`, `.agents/skills/moon-courier-sdd/SKILL.md`,
`tasks/T011-four-levels.md`, `features/F011-four-levels.md`,
`specs/gameplay/09-levels-balance.md`, `specs/technical/06-map-validation.md`,
`specs/technical/10-assets-tiles.md`, `contracts/examples/*`,
`references/04-map-risk-topology.png` и только непосредственно связанные
content/runtime/simulation/UI/test файлы.

Фактические пробелы до реализации:

- production runtime и selector знали только один Shackleton bundle;
- `createRuntimeMap` не передавал `levelOrdinal`, поэтому часть topology rules
  фактически не применялась;
- content script валидировал документы по одному и не доказывал cross-references,
  risk share, безопасные альтернативы или playable production catalog;
- contract не моделировал ordinal/risk/набор центров с seeded equipment needs;
- текущий atlas объявлял 361 tile и занимал 3.55 MB, хотя карты использовали
  только три логических tile; `THIRD_PARTY_NOTICES.md` оставался placeholder;
- четыре полноразмерных preview одновременно нарушили бы смысл initial-load
  budget, поэтому selector должен загружать фон только выбранного уровня.

| Shackleton  | 16×10 / (1,5)  | Helios, Aristarchus; 2/3           | x6..9, y2..7; 24     | 18/12 = 1.50; 19/13 = 1.46; Kepler direct 1.0  |

Два безопасных обхода образуются соответственно по `y=2/y=6`, `y=1/y=8`,
`x=5/x=13` и `y=1/y=11`. Все ratios и связность независимо пересчитаны BFS.

### Решения

- В level metadata добавить обязательные `ordinal`, `riskLevel` и
  `seededEquipmentDemandCenterIds`; длина последнего равна ordinal, ID уникальны
  и принадлежат centers.
- Production-каталог хранить в `src/content/levels`, а общий balance/incidents/
  radio переиспользовать; runtime всегда валидирует bundle с ordinal.
- Сохранить все карты статическими: procedural generation и auto-routing не
  добавлять. BFS используется только валидатором/tests.
- Переиспользовать четыре object sprites, сократить общий atlas до реально
  используемых логических tiles и создать только три новых оригинальных фона.
  Полный preview существует только для выбранной карточки.
- Generated assets не объявлять CC0; в реестре указать provenance. Сторонние
  NASA/Kenney/Game-icons материалы не добавлять.

### План

1. Зафиксировать T011 `in_progress`, spec-audit и requirement→evidence.
2. Добавить red tests каталога, contracts/equipment seed, топологии и budgets.
3. Расширить content contracts, simulation config и production validators.
4. Создать четыре статических level bundles и оптимизированные локальные assets.
5. Подключить production catalog к runtime, selector и briefing.
6. Добавить deterministic smoke всех уровней и Playwright flows.
7. Выполнить три quality-прохода и исправить только доказанные расхождения.
8. Обновить CODEMAP, отчёт и manifest, затем перейти к T012.

## Результат

Реализован production-каталог из четырёх статических Tiled-уровней. Каждый
уровень имеет собственные metadata/theme/map/background, нормативный состав
центров и роверов, крупную связную hazard-зону и проверяемые безопасные/короткие
варианты маршрута. Selector создаёт изолированную runtime-сессию выбранной
карты; briefing и Phaser получают её фактические параметры.

Level metadata теперь являются источником `ordinal`, risk level и точного набора
центров с начальной потребностью в оборудовании. Все четыре уровня завершаются
`VICTORY` детерминированным test-side диспетчером за 960 шагов по 500 ms. Smoke
делает реальные `LOAD_CARGO`/route/unload/return/charge действия, доставляет груз
во все центры и оборудование во все seeded-центры, запрещает `LOST` и проверяет
конечность всех чисел snapshot.

Четыре фона приведены к 2048×1536 и остаются ниже 600 KB. Production logical
atlas содержит три прозрачных tile и занимает 3 789 B; неиспользуемый atlas на
3 554 253 B удалён. Нормализация стандартных Tiled layer defaults делает WebP
Image Layer реально видимым под прозрачной сеткой/hazard overlay в Phaser.

## Три прохода

1. **Спецификация.** Requirement matrix сверена с task/feature/gameplay/map/assets
   specs. Найдены и исправлены канонические размеры фонов, забытый legacy atlas,
   отсутствие прозрачности logical tiles и runtime defaults Tiled Image Layer.
2. **Простота и границы.** Независимый review нашёл ложную multiplicity для
   trivial/direct edge, center overlaps, слабую JSON Schema parity и отсутствие
   theme↔Tiled background cross-reference. Исправлены точечно; новых библиотек,
   gameplay-правил в React/Phaser и runtime auto-routing не добавлено.
3. **Регрессия и сценарий.** Полный gate, dev E2E и nginx E2E зелёные. Просмотрены
   selector/map screenshots всех уровней; console/page/network/HTTP errors
   отсутствуют. Synthetic canvas-click под нагрузкой один раз не дошёл до Phaser;
   E2E повторяет его максимум один раз и только если тот же candidate всё ещё
   валиден, после чего full suite и тройной isolated stress прошли.

## Допущения

- Selector сначала показывает default Shackleton preview. После выбора другой
  карты browser resource log может содержать default + выбранный фон, но никогда
  не загружает все четыре; в DOM всегда один `<img>`.
- Smoke использует детерминированный test-side BFS только по `normal` клеткам и
  вручную отправляет команды engine. Runtime не получил auto-routing.

## Зависимости и лицензии

Новых npm-зависимостей нет. Три новых фона созданы для проекта через OpenAI
ImageGen; Shackleton-фон и object sprites были созданы тем же способом в T009.
WebP/PNG перекодированы локальным Chromium pipeline. Logical atlas программно
нарисован Canvas; внешние NASA/Kenney/Game-icons/OpenGameArt файлы не включены.
Provenance зафиксирован в `THIRD_PARTY_NOTICES.md`.

## Остаточные риски

- Vite предупреждает о minified lazy Phaser chunk 1 393 KB (gzip 364 KB). Он
  загружается только после старта смены и укладывается в asset/load budgets;
  release performance policy относится к T012.
- В headless Chromium под высокой нагрузкой единичный synthetic pointer event
  может не дойти до canvas; bounded E2E retry не скрывает неверный candidate и
  проверен последовательным stress-run. Обычный повтор клика пользователем
  безопасен, состояние route draft не повреждается.
