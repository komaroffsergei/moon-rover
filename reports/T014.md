# Отчёт T014

## Результат

Реализованы пять требований F014 без запуска следующей задачи.

- При конечном прибытии в любой научный центр курьер автоматически передаёт
  кислород, пайки и оборудование до capacity. Из cargo вычитается только
  фактически принятый объём; избыток и дробный остаток остаются у ровера.
- Hazard-маска каждой карты рисуется единым детерминированным органическим
  контуром с крупными асимметричными выступами и впадинами. Внутренние клеточные
  швы отсутствуют; повороты многосегментного маршрута скруглены, cell markers не
  рисуются.
- `FREE_NAVIGATION` строит детерминированный visibility-маршрут под произвольным
  углом. Conservative supercover запрещает пересечение blocked-рельефа и
  срезание углов; score учитывает евклидову длину, terrain cost и прежний
  incident risk.
- Ровер хранит дробную позицию и непрерывно расходует время/батарею по длине
  сегмента. Cell-entry происшествия обрабатываются один раз. ПКМ во время
  движения атомарно строит путь из точной live-position, включая немедленный
  U-turn без скачка; невозможная цель сохраняет прежнее состояние.
- Каждая production-сессия получает новый Web Crypto placement seed: безопасная
  база выбирается из валидированных authoring-якорей, центры процедурно
  размещаются по distinct interior walkable/LOS-reachable клеткам. Hazard
  разрешён, blocked запрещён, все роверы стартуют на выбранной базе. Одинаковый
  seed воспроизводим, E2E authoring override сохранён.

Финальный Docker verify прошёл: 43 test files / 452 tests. Полный test-mode
Playwright прошёл 14/14 исполняемых сценариев, production-only boundary штатно
пропущен. Свежий production nginx healthy на `http://localhost:8080`, отдельная
production boundary прошла 2/2.

## Spec-audit и план до кода

До production-кода были прочитаны AGENTS, skill, T014/F014, связанные
product/gameplay/UI/technical living specs и quality workflow. Аудит
зафиксировал:

- запрос заменяет D001 с четырьмя направлениями, D005 recovery-only auto-unload
  и D006 с обязательным завершением старого ребра;
- «восполнить полностью» ограничено conservation: передаётся
  `min(cargo, capacity - stock)`, недостающий груз не создаётся;
- GridCell остаётся единицей авторинга, incident entry и конечной ПКМ-цели, но
  позиция и движение между точками становятся дробными и произвольного угла;
- runtime и content acceptance обязаны использовать одно LOS/supercover
  правило. Cardinal D007 остаётся только исторической authoring-метрикой
  safe/short 1.4–1.9 и не управляет runtime-маршрутом;
- случайное размещение означает независимую новую выборку при reload, а не
  математическую гарантию отличия от предыдущей; одинаковый seed детерминирован;
- hazard-центр допустим, поэтому прежний safe-only runtime placement больше не
  является постусловием.

План до кода, 8 пунктов:

1. Зафиксировать T014/F014, обновить противоречащие living specs и regressions.
2. Ввести any-angle LOS/supercover-навигацию с евклидовой стоимостью.
3. Перевести route state и движение на дробную позицию и cell-entry effects.
4. Сделать атомарный live-position reroute и немедленный U-turn.
5. Реализовать процедурное размещение центров с hazard-кандидатами.
6. Переключить arrival на полную capped-разгрузку с conservation.
7. Добавить органический hazard contour и скруглённый маршрут без клеток.
8. Выполнить три quality-прохода, отчёт T014 и остановиться.

## Допущения

- «Полностью» означает до capacity только при наличии достаточного cargo;
  недостаток груза не создаёт ресурс.
- Новый reload получает независимый Web Crypto seed; случайное совпадение двух
  раскладок допустимо. Explicit seed остаётся воспроизводимым.
- Конечная ПКМ-цель — центр walkable GridCell; sub-cell ручная цель и физические
  столкновения не входят в T014.
- Cardinal D007 остаётся только authoring balance metric. Runtime и procedural
  reachability используют any-angle conservative LOS.

## Зависимости и остаточные риски

Новых npm-зависимостей, лицензий и ассетов нет. Использованы существующие
pure-rand, Phaser и Web Crypto.

Pixel-perfect snapshot всей лунной текстуры намеренно не закреплён: органическая
геометрия проверяется чистыми deterministic tests, реальным Playwright и
просмотренными кадрами. Известных функциональных расхождений по T014 нет.
Следующая задача не начата.
