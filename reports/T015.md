# Отчёт T015

## Результат

Реализованы требования F015-R1–R5 без запуска следующей задачи.

- Исправная ремонтная бригада после конечного прибытия на клетку сломанного
  meteorite-курьера или на соседнюю cardinal-клетку автоматически начинает
  штатный пятиминутный ремонт. Проезд мимо не запускает операцию; crater rescue
  и передача батареи остаются явными действиями.
- Comic-реплики центров и роверов получили различимый крестик. Закрывается
  только выбранная реплика, slot освобождается сразу, а исходное сообщение
  остаётся в журнале рации и не проигрывается повторно.
- У каждого ровера показано убывающее зелёно-графитовое кольцо батареи. Над
  courier rover отображаются три компактные линии oxygen/food/equipment;
  repair rover не получает ложный cargo HUD.
- Игровой экран стал full-map: постоянные верхняя, боковые и нижняя панели
  удалены. Inspector появляется справа сверху только для выбранного объекта и
  сворачивается без сброса selection/маршрута. Слева снизу оставлены пауза и
  рация; рация открывается отдельным сворачиваемым drawer.
- Добавлен пятый уровень `Лабиринт Эйткена` с risk `maximum`: шесть центров,
  пять курьеров, один repair rover, пять seeded equipment demands, несколько
  отдельных крупных hazard-зон, blocked-рельеф и уникальный локальный WebP.

Финальный Docker verify прошёл: 44 test files / 469 tests. Единый dev
Playwright прошёл 15/15 исполняемых сценариев, production-only boundary штатно
пропущен; отдельный production boundary прошёл 1/1. Production nginx healthy на
`http://localhost:8080`.

## Spec-audit и план до кода

До production-кода были прочитаны `AGENTS.md`, skill
`.agents/skills/moon-courier-sdd/SKILL.md`, manifest, prompt T015, feature/task
specs, связанные product/gameplay/UI/technical living specs и
`quality/THREE_PASS_WORKFLOW.md`. Аудит зафиксировал:

- автоматизация распространяется только на meteorite-ремонт и запускает
  существующую валидируемую emergency operation после конечного
  `ROVER_ARRIVED`;
- deterministic priority при нескольких целях: same-cell, затем стабильный ID;
  ручной fallback сохраняется для курьера, сломавшегося возле уже стоящего
  ремонтника;
- закрытие bubble не изменяет domain event и radio journal;
- Phaser HUD является только snapshot projection и не рассчитывает gameplay;
- стационарный layout заменяется full-bleed картой и временными floating
  surfaces; сворачивание inspector не меняет selection;
- progression/content contracts расширяются с четырёх до пяти уровней без
  скрытых коэффициентов incident/depletion и без изменения 480-секундной смены;
- новый bitmap нужен только пятой карте, UI и текст остаются code-native.

План до кода, 8 пунктов:

1. Зафиксировать T015/F015 и обновить конфликтующие living specs.
2. Добавить regression tests автозапуска ремонта и deterministic выбора цели.
3. Реализовать закрываемые реплики и rover battery/cargo HUD в Phaser.
4. Перестроить GameScreen в full-map HUD с inspector и radio drawer.
5. Добавить валидируемую пятую maximum-карту и локальный background.
6. Выполнить целевые проверки и визуальную сверку с концептом.
7. Провести три quality-прохода, полный Docker gate и E2E.
8. Создать `reports/T015.md`, завершить manifest и остановиться.

## Основные изменённые зоны

- Simulation arrival/rescue — автоматический выбор цели и запуск канонической
  repair operation после прибытия, точное применение fractional fixed-step
  remainder и прежний manual fallback.
- `src/game/MapScene.ts` и presentation geometry — close-hit-area реплик,
  battery/cargo HUD, раздельные selection/incident markers, органическая
  штриховка всех hazard-компонентов и читаемое разведение шести роверов.
- React UI/store/styles — полноэкранная карта, условный и сворачиваемый selected
  inspector, radio drawer, две нижние левые кнопки, сохранённые keyboard/modal
  сценарии; удалён постоянный overview panel.
- Content/contracts/assets — ordinal 5, risk `maximum`, bundle Эйткена, четыре
  authoring layout, procedural/runtime projection и локальный
  `public/assets/maps/aitken/background.webp` 2048×1536 / 580466 B.
- Unit/content/React/Playwright — regressions требований, все пять карт,
  fullscreen geometry, bubbles, HUD, delivery, routing и production boundary.
- Product/gameplay/UI/technical specs, README, CODEMAP, CONTENT_REFERENCE,
  MAP_AUTHORING и TESTING приведены к фактическому поведению T015.

## Допущения

- Auto-repair не распространяется на crater rescue и battery transfer.
- Manual repair fallback сохраняется для инцидента, возникшего возле уже
  припаркованной бригады.
- HUD не является источником gameplay-значений; дробные simulation quantities
  сохраняются, отображение округляется.
- Maximum-сложность задаётся контентом и топологией, а не скрытыми runtime
  множителями.
- Случайное procedural placement означает независимую выборку при новой
  сессии; explicit seed остаётся воспроизводимым.

## Зависимости и остаточные риски

Новых production-зависимостей и внешних runtime-ресурсов нет. Фон Эйткена —
локальный сгенерированный asset проекта; production не обращается к сети за
картой или UI.

Pixel-perfect snapshot всей лунной текстуры намеренно не закреплён: геометрия
HUD/hazard проверяется deterministic unit tests, реальным Playwright и
просмотренными кадрами. Известных функциональных расхождений по F015 нет.
Следующая задача не начата.
