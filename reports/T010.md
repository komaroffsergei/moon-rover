# Отчёт T010

## План до кода

**Цель:** собрать вокруг неизменяемой Phaser-карты компактный React-интерфейс
диспетчера со всеми нормативными экранами, состояниями, доступными действиями и
клавиатурным управлением, не перенося правила simulation в UI.

**Контекст:** `AGENTS.md`, `.agents/skills/moon-courier-sdd/SKILL.md`,
`tasks/T010-react-ui.md`, `features/F010-react-ui.md`,
`specs/ui/01-screen-map.md`, `02-main-layout.md`,
`03-interaction-states.md`, `04-visual-style.md`, `05-accessibility.md` и только
непосредственно связанные app/game/controller/store/test файлы.

Реальные integration gaps и минимальные решения:

- T011 владеет четырьмя production maps, поэтому T010 строит data-driven selector
  из единственного сейчас валидированного Shackleton level; selector расширяется
  каталогом T011 без фиктивных карт/чисел.
- `MapGameController` разделит `selectedEntity` и `routeDraft`, получит
  subscription и typed command bridge. `MapScene.update()` останется
  единственным местом `advance()`; React не создаёт второй simulation timer.
- Прогноз исчерпания центра проектируется app-adapter из validated level
  definitions и snapshot. React получает готовое значение и не знает
  depletion coefficients.
- Формулировка «rescue/transfer confirmation» ограничена явным modal whitelist:
  rescue/repair запускаются inline action, confirm dialog применяется только к
  передаче батареи.
- Domain route confirm+dispatch атомарен, поэтому UI показывает одно явное
  действие «Отправить маршрут» без фиктивной дополнительной модалки.

### Визуальная production-спецификация

- Принятый concept: `references/generated/T010-dispatcher-concept.png`.
- 1920×1080: 60 px top bar, 260 px left, 320 px right, 48 px route dock; на
  1280×720 панели сжимаются до 190/240 px, чтобы map host остался ≥65% ширины.
- Near-black/navy surfaces без градиентов и glow-heavy эффектов; 1 px blue-gray
  borders, небольшие 2–6 px radii, карта визуально главнее chrome.
- Oxygen cyan, food green, equipment amber, hazard/recovery/error red/burgundy;
  каждый статус дополнен текстом/иконкой/рамкой.
- UI copy только из specs/validated content/snapshot; нет currency, player
  profile, global stock, chat input, auto-routing и дополнительных целей.
- Phaser загружается динамически только при игровом экране; статические selector
  и briefing не платят за тяжёлый bundle до запуска смены.

### Риски

- Второй React clock ускорит simulation — advance остаётся только в Phaser,
  controller публикует throttled readonly view.
- 65% map width конфликтует с фиксированными панелями на 1280 — размеры
  проверяются через реальные bounding boxes, а не только CSS declarations.
- Keyboard handlers могут перехватить cargo controls — Space/Esc проверяют
  interactive target и dialog precedence.

## Результат

Реализован полный desktop flow `level select → briefing → game` для текущего
validated уровня. Игровой экран получил компактный HUD, взаимоисключающие
вкладки центров/роверов, выбранную сущность и действия, рацию/журнал, HTML route
dock, recovery/rescue states и разрешённые pause/battery/final dialogs. Реальные
canvas-интеракции выбирают сущность, а route mode включается только явной
кнопкой; selection сохраняется после dispatch.

Simulation/Phaser остаются единственными владельцами правил и времени. MapScene
по-прежнему единственная вызывает `advance`; controller публикует readonly view
не чаще 100 ms, а per-session vanilla Zustand store хранит только view и UI
state. Доступность cargo/route/charge/unload/repair/rescue/battery actions теперь
проецируется в simulation и не вычисляется React. UI-store структурно связан с
game-port только в `src/app`, без прямого `ui/store → game` импорта.

Phaser и `GameScreen` загружаются динамически после старта смены. Production
build разделён на eager entry 368.08 kB (gzip 109.19), GameScreen 22.94 kB
(gzip 6.55) и Phaser/createGame 1,393.18 kB (gzip 364.05).

## Три прохода

1. **Спецификация.** Для каждого критерия добавлено evidence. Реальные
   расхождения исправлены: direct selection раньше включал route mode; не было
   controller subscription/level flow; map recovery не имел текста/timer;
   крайние labels обрезались; action availability находилась в React; зарядка
   `OUT_OF_BATTERY` ровера на базе скрывалась. Первый middle-pan E2E корректно
   выявил, что fit-карту нельзя сдвинуть до zoom; тест переставлен после wheel
   zoom без ослабления assertions.
2. **Простота и границы.** Удалены canvas HUD/route buttons и дублирующие
   React emergency rules. Store больше не импортирует game port и закреплён как
   UI policy отрицательными ESLint fixtures. Нет новых runtime dependencies,
   второго clock, timers, UI framework/router или direct mutation. Phaser и
   GameScreen lazy-loaded; controller/store cleanup idempotent.
3. **Регрессия.** Fresh verify прошёл 310 unit/integration tests, 6 content
   documents и production build. Один и тот же pointer/keyboard flow прошёл на
   Vite и nginx. Просмотрены шесть финальных screenshots; итоговые CODEMAP,
   report и scope сверены.
