# Отчёт T008

## План до кода

**Цель:** преобразовывать domain events в валидированные локализованные
сообщения рации с bounded history, дедупликацией и ссылкой на источник.

**Контекст:** `AGENTS.md`, `.agents/skills/moon-courier-sdd/SKILL.md`,
`tasks/T008-radio.md`, `features/F008-radio.md`,
`specs/gameplay/08-radio.md`, `specs/gameplay/03-centers-resources.md`,
`specs/gameplay/06-hazards-events.md`, `contracts/radio.schema.json`,
`contracts/examples/radio.ru.json`, `reports/T007.md` и непосредственно
связанные DomainEvent/content loader/simulation engine файлы.

### Spec-audit

| ID      | Наблюдаемое поведение                                                                                                | Проверка                                 |
| ------- | -------------------------------------------------------------------------------------------------------------------- | ---------------------------------------- |
| T008-R1 | Каждый обязательный eventCode имеет JSON templates ≤180 символов, category и priority                                | schema/example positive + negative tests |
| T008-R2 | Один DomainEvent создаёт ноль или одно сообщение; один recovery transition не дублируется start+threshold событиями  | exhaustive mapping/cardinality tests     |
| T008-R3 | Oxygen/food 50/25/10/5/1 и recovery 30/20/10/5/1 форматируются отдельными локализованными кодами                     | threshold/recovery matrices              |
| T008-R4 | Новые сообщения находятся сверху, история ограничена 100 элементами                                                  | 101-event bounded-history test           |
| T008-R5 | Повтор одного event fingerprint подавляется, но новый threshold episode с другим gameMinute разрешён                 | exact duplicate/new-episode tests        |
| T008-R6 | Сообщение сохраняет objectId, cell, source kind, category и priority для будущего фильтра/клика                      | center/rover/rescue/system source matrix |
| T008-R7 | Incident/rescue/transfer/outcome события имеют semantic templates; 1% censored noise находится только в JSON         | mapping + content-location assertions    |
| T008-R8 | Engine snapshot serializable и получает сообщения как из `advance`, так и из event-producing command без DOM/UI/chat | public-engine integration/snapshot tests |

Нормативные пробелы закрываются минимально. Category и priority являются частью
валидируемого template content, но порядок истории всегда newest-first, без
priority-сортировки. Dedupe key включает eventCode, objectId, gameMinute и
значимый payload: повторная доставка того же события не создаёт шум, а новое
пересечение того же порога позднее остаётся видимым. `CENTER_RECOVERY_STARTED`
не создаёт отдельную реплику, потому что тот же transition уже содержит
`RECOVERY_THRESHOLD(30)`. Для массива вариантов детерминированно используется
первый template; runtime-random и генеративного текста нет.

Cell фиксируется в самом DomainEvent в момент возникновения, поэтому более
позднее положение ровера не искажает цель исторического сообщения. ObjectId
остаётся основной долговечной ссылкой для будущего клика. DOM-компонент, mouse
handler и фактическое центрирование карты относятся к T009/T010 и прямо
исключены T008; эта задача предоставляет достаточный typed target contract.

  generative/random text.

### Риски

- Два domain events одного recovery transition могут дать две реплики — mapping
  должен явно оставлять start event без сообщения.
- Бесконечный dedupe или ключ без времени скроет легитимный новый threshold
  episode — fingerprint и boundary закрепляются тестом.
- Сообщение из command может потеряться при обработке только `advance` — engine
  integration должна использовать общий append path.

## Результат

Доменные события теперь детерминированно преобразуются в локализованные
сообщения рации из валидированного JSON catalog. Public snapshot хранит новые
сообщения сверху, ограничивает историю последними 100 и сохраняет category,
priority, source kind, objectId и координату источника на момент события.

Полностью покрыты oxygen/food 50/25/10/5/1, recovery 30/20/10/5/1,
restored/lost, equipment demand, rover arrival/battery, incidents,
repair/rescue/transfer и исход смены. Courier и repair unit получают разные
incident templates: курьеру сообщается требуемое действие, ремонтной бригаде —
правдивое самовосстановление. Тексты, включая `[помехи]` на 1%, остаются только
в JSON; runtime выбирает первый вариант без RNG и не содержит input/chat.

Exact fingerprint подавляет повторную доставку, но допускает новый эпизод в
другую игровую минуту. Коррелированные completion/resolved и
transfer/out-of-battery пары дают одну предпочтительную rescue-реплику вне
зависимости от порядка или разбиения `ingest`. Внешней границей остаётся только
`GameSnapshot.radioMessages`; journal plumbing не опубликован.

## Три прохода

1. **Спецификация.** Все R1–R8 связаны с content/unit/integration tests.
   Исправлены ложные инструкции repair rover через courier/repair templates,
   historical cell перенесена в DomainEvent, а Zod/JSON Schema/engine получили
   одинаковое placeholder-правило.
2. **Простота и границы.** Удалён clone-only adapter и публичный journal return/
   export; React/Phaser/chat/RNG не добавлялись, коэффициентов и новых
   зависимостей нет. Bounded state хранит максимум 100 entries. Три независимых
   post-review не нашли оставшихся P0–P2.
3. **Регрессия.** После исправлений повторён immutable gate: 221/221 tests,
   content 6/6 и build green. Единичный boundary timeout воспроизведён отдельно
   как 20/20 green, повторный полный gate прошёл. Playwright mouse scenario 1/1;
   console, network, layout 1280×720 и CODEMAP сверены.

## Допущения

- Category/priority приходят из content, но не меняют newest-first порядок.
- Для нескольких templates детерминированно используется первый; runtime RNG
  намеренно отсутствует.
- Fingerprint включает code, object/payload, gameMinute и event-time cell:
  повтор той же доставки скрывается, новый поздний эпизод остаётся видимым.
- `CENTER_RECOVERY_STARTED` не создаёт реплику: парный `RECOVERY_THRESHOLD(30)`
  уже представляет тот же transition.
- В коррелированной паре rescue completion/transfer является более полезным
  сообщением и заменяет generic resolved/out-of-battery.
