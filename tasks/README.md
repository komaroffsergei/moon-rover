# Выполнение task manifest

`manifest.json` — machine-readable маршрутизатор SDD, а не источник игровых правил.

## Состояния

```text
pending → in_progress → completed
                      ↘ blocked
```

- В начале сеанса менять только выбранную задачу на `in_progress`.
- `completed` допустим только после отчёта и зелёных обязательных проверок.
- `blocked` ставится при существенном конфликте/невыполнимой зависимости; причина находится в `reports/Txxx.md`.
- Codex не меняет статусы будущих задач и не начинает следующую в том же сеансе.

## Context allowlist

Поле `context` задаёт первичное чтение. Glob-пути вроде `contracts/*.schema.json` ограничены указанным каталогом. Открытие дополнительной спецификации требует конкретной причины в spec-audit.

## Проверка

`manifest.json` должен соответствовать `manifest.schema.json`; ID уникальны, зависимости ссылаются только на существующие более ранние задачи, prompt/task/feature/context существуют.
