# T006. Движение и неблагоприятные события

**Feature spec:** `features/F006-movement-incidents.md`  
**Зависит от:** T005

## Цель

Исполнять подтверждённые маршруты и воспроизводимо разыгрывать события на входе в клетки.

## Контекст задачи

Открыть только перечисленные файлы и уже созданный код, непосредственно связанный с задачей:

- `features/F006-movement-incidents.md`
- `specs/gameplay/06-hazards-events.md`
- `specs/gameplay/09-levels-balance.md`
- `specs/gameplay/10-state-model.md`
- `specs/technical/04-simulation.md`
- `contracts/incidents.schema.json`

Не читать весь пакет «на всякий случай». Если нужное правило отсутствует, применить порядок приоритетов из `README.md`.

## В scope

- пошаговое движение с интерполяционным progress;
- расход батареи;
- seeded RNG pure-rand;
- обычный и повышенный риск;
- cooldown после события;
- пылевая буря, метеорит, кратер;
- самовосстановление repair unit;

## Ожидаемые результаты

- `src/simulation/movement/*`;
- `src/simulation/incidents/*`;
- `src/shared/random/*`;
- `fixtures с фиксированными seed`;

Конкретные имена внутренних файлов можно скорректировать, если сохраняются границы ответственности и это объяснено в отчёте.

## Критерии приёмки

- [ ] один seed даёт одинаковую последовательность;
- [ ] событие проверяется только при входе в клетку;
- [ ] активное событие не накладывается повторно;
- [ ] пылевая буря длится 10 игровых минут;
- [ ] meteorite блокирует courier до ремонта;
- [ ] repair unit самостоятельно выходит из любого события через 10 игровых минут;
- [ ] нулевая батарея останавливает движение;

## Не входит

- визуальные эффекты;
- спасение другим ровером;
- баланс финальных карт;

## Обязательный рабочий цикл

1. До изменений записать план максимум из 8 пунктов.
2. Найти самый маленький законченный вертикальный срез задачи.
3. Сначала добавить/уточнить проверяемые тесты или валидаторы требования.
4. Реализовать минимальный код, необходимый для прохождения этих проверок.
5. Запустить команды через Docker из `quality/THREE_PASS_WORKFLOW.md`.
6. Просмотреть итоговый diff и удалить код, не нужный этой задаче.
7. Создать `reports/T006.md` по `quality/REPORT_TEMPLATE.md`.

## Запрет завершения

Задача не считается выполненной по фразе «должно работать». В отчёте нужны фактические команды, их результат и ссылки на тесты, доказывающие каждый критерий.
