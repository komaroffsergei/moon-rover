# T005. Ручное построение маршрута

**Feature spec:** `features/F005-manual-route.md`  
**Зависит от:** T004

> **Статус: superseded by D006 / user-directed T012 revision.** Это исторический
> prompt выполненной T005. Решение D006 и направленная владельцем продукта
> ревизия T012 заменили описанный ниже
> ручной route draft на выбор ровера левым кликом и немедленное назначение
> другой достижимой проходимой клетки правым кликом. Текущий runtime строит
> детерминированный Dijkstra с валидированными весами и не показывает сетку,
> кандидатов, undo/clear или подтверждение. Исходный текст оставлен только как
> историческое свидетельство и не должен запускаться повторно.

## Цель

Дать игроку возможность задавать и менять маршрут последовательными кликами по соседним клеткам.

## Контекст задачи

Открыть только перечисленные файлы и уже созданный код, непосредственно связанный с задачей:

- `features/F005-manual-route.md`
- `specs/gameplay/05-manual-routing.md`
- `specs/gameplay/10-state-model.md`
- `specs/technical/06-map-validation.md`
- `contracts/tiled-layer-contract.md`

Не читать весь пакет «на всякий случай». Если нужное правило отсутствует, применить порядок приоритетов из `README.md`.

## В scope

- 4-соседство;
- проходимость;
- undo/clear/confirm;
- маршрут до базы или центра;
- перенаправление исправного ровера;
- прогноз длины, времени, батареи и риска;

## Ожидаемые результаты

- `src/simulation/routing/*`;
- `команды маршрута`;
- `unit-тесты маршрута и прогноза`;

Конкретные имена внутренних файлов можно скорректировать, если сохраняются границы ответственности и это объяснено в отчёте.

## Критерии приёмки

- [ ] диагональный и несоседний клик отклоняются;
- [ ] препятствие отклоняется;
- [ ] повтор последней клетки отменяет шаг только по явной команде undo;
- [ ] подтверждённый путь неизменяем как value object;
- [ ] прогноз использует те же функции стоимости, что движение;
- [ ] A* и автопоиск отсутствуют;

## Не входит

- мышиный ввод Phaser;
- анимация движения;
- помощник автоматического маршрута;

## Обязательный рабочий цикл

1. До изменений записать план максимум из 8 пунктов.
2. Найти самый маленький законченный вертикальный срез задачи.
3. Сначала добавить/уточнить проверяемые тесты или валидаторы требования.
4. Реализовать минимальный код, необходимый для прохождения этих проверок.
5. Запустить команды через Docker из `quality/THREE_PASS_WORKFLOW.md`.
6. Просмотреть итоговый diff и удалить код, не нужный этой задаче.
7. Создать `reports/T005.md` по `quality/REPORT_TEMPLATE.md`.

## Запрет завершения

Задача не считается выполненной по фразе «должно работать». В отчёте нужны фактические команды, их результат и ссылки на тесты, доказывающие каждый критерий.
