# Исследование технологий и ассетов

Дата фиксации: 13 августа 2026. Перед массовым обновлением зависимостей повторить проверку, но не обновлять их посреди feature-задачи.


## Tooling-линии

Node 24 выбран как LTS; pnpm 11 совместим с ним и фиксируется через `packageManager`/Corepack. Vite 8 и Vitest 4 используют одну современную toolchain-линию, а TypeScript работает в `strict`. Zod 4 валидирует входной контент, pure-rand изолирует seeded RNG. Версии фиксируются lockfile в T001; автоматическое массовое обновление посреди разработки запрещено.

## Карта и движок

### Выбор: Phaser 4 + Tiled JSON

Phaser уже даёт WebGL/Canvas-рендеринг, камеру, input, спрайты и Tilemap. Tiled является отдельным бесплатным редактором уровней и экспортирует JSON, который Phaser парсит. Для Phaser Tiled parser внешний tileset через `source` не поддерживается, поэтому в проекте фиксируются embedded tilesets.

Это проще MapLibre для текущей игры: координаты являются `row/column`, маршрут кликается по клеткам, а карта состоит из четырёх конечных уровней. Геопроекция, глобальные тайлы и lng/lat не дают игровой пользы.

## UI

React используется только для DOM-панелей, рации и экранов; Zustand — как тонкий bridge snapshot/actions. Никаких Redux/XState. Phaser canvas и React DOM имеют отдельные ответственности.

## Тайлы и лунная подложка

### Рекомендованный production-подход

1. Один локальный фон уровня 1920×1080 или близкого aspect ratio в WebP, 250–700 KiB.
2. Небольшой tileset 32×32 или 48×48 для логических покрытий/краёв/паттернов, желательно 256×256 или 512×512 atlas.
3. Danger zones и grid рисуются программно/простым overlay, а не десятками уникальных тяжёлых тайлов.
4. База, центры и роверы — отдельные WebP/PNG sprite sheets.
5. Tiled хранит логику и размещение, а не мегабайты встроенных картинок.

Так фон выглядит естественно, а сетка остаётся дешёвой и легко заменяемой стилем.

### Бесплатные источники

- **NASA CGI Moon Kit**: цветовые и высотные карты, созданные из LRO/LOLA; подходит как исходник для подготовки четырёх фонов. Исходники могут быть очень большими, поэтому в игру кладётся только обработанный crop/WebP, не глобальная текстура.
- **Kenney UI Pack — Sci-Fi**: CC0, 130 UI-файлов; использовать выборочно для рамок/кнопок или как источник направления.
- **Kenney Interface Sounds**: CC0, 100 коротких звуков; выбрать 6–10 и перекодировать в OGG/MP3.
- **Game-icons.net**: SVG/PNG под CC BY 3.0; использовать только если ведётся атрибуция авторов. Для минимизации юридической рутины сначала предпочесть собственные SVG/CC0 Kenney.
- **OpenGameArt: Moon Surface 2D**: 120.6 KiB, SVG внутри архива, CC BY 3.0. Очень лёгкий вариант для прототипа/placeholder, но визуально старый и недостаточно подробный для реалистичной финальной карты.
- **OpenGameArt: Space Isometric Pixel Art**: CC0, 74.4 KiB, 54 тайла и 20 декораций. Хороший бесплатный набор, но изометрическая перспектива конфликтует с выбранной ортогональной картой; использовать только при официальной смене арт-направления.

### Итог по готовым тайлам

Готового лёгкого CC0-набора, который одновременно даёт реалистичную Луну, ортогональный top-down, крупные danger overlays и нужные здания/роверы, не найдено. Поэтому не следует подгонять геймплей под чужой набор: production-вариант — четыре обработанных NASA crop/WebP плюс собственный крошечный логический atlas из нескольких простых паттернов. Это меньше работы, чем художественно согласовывать десятки несовместимых пакетов.

### Что не рекомендуется

- runtime NASA/WMTS/MapLibre;
- тяжёлые 4K/8K исходники в `public`;
- скачивание случайного tileset с агрегатора без лицензии;
- 3D-модели для 2D MVP;
- сотни неиспользуемых файлов asset pack;
- remote CDN.

## Бюджет ассетов

| Категория | Цель |
|---|---:|
| 4 фоновых WebP | до 3 MiB суммарно |
| tileset/patterns | до 512 KiB |
| роверы/центры/VFX | до 2 MiB |
| UI icons | до 512 KiB |
| звуки | до 1.5 MiB |
| общий initial asset budget | до 8 MiB |

Бюджет является ориентиром T011. Увеличение требует измерения и записи причины, не философской лекции о качестве текстур.

## Codex и SDD

Корневой `AGENTS.md` хранит только постоянные правила; feature/task документы подгружаются по необходимости. Skill использует progressive disclosure. Одна задача выполняется за один сеанс, затем создаётся короткий отчёт. Это снижает повтор контекста и уменьшает шанс, что агент смешает требования разных этапов.
