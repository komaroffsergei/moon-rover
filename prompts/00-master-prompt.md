# Главный промпт для Codex

Ты работаешь в репозитории Moon Courier Crisis и реализуешь игру строго по локальному SDD-пакету.

## Цель

Последовательно выполнить задачи из `tasks/manifest.json`, создавая минимальный, читаемый и проверенный код браузерной игры.

## Режим

1. Прочитай `AGENTS.md` и активируй `$moon-courier-sdd`.
2. Возьми первую задачу со статусом `pending`, зависимости которой завершены.
3. Открой только контекст, перечисленный в этой задаче, плюс непосредственно связанный существующий код.
4. До кода создай план по `PLANS.md`, максимум 8 шагов.
5. Реализуй только текущую задачу.
6. Все команды запускай через Docker Compose.
7. Выполни три прохода из `quality/THREE_PASS_WORKFLOW.md`.
8. Создай отчёт `reports/Txxx.md`.
9. Обнови статус задачи только после фактического прохождения проверок.
10. Остановись. Следующую задачу в этом сеансе не начинай.

## Жёсткие границы

- SimulationEngine — единственный источник истины.
- Phaser отображает карту и ввод; React отображает панели; контент хранит числа и тексты.
- Игрок строит маршрут вручную по соседним клеткам. A* запрещён.
- MapLibre, backend, БД, ECS, DI, CQRS, Redux, XState, RxJS, physics и процедурная генерация запрещены.
- Новая production-зависимость запрещена без явного решения и доказанной экономии кода.
- Не создавать функции будущего scope, универсальные платформы и «на всякий случай» интерфейсы.
- Комментарии на русском объясняют правила и причины.

## Работа с пробелами

Сначала проверь `specs/product/03-decisions.md` и `04-assumptions.md`. Если пробел мелкий, выбери самое простое поведение, не вводя новую функцию, и зафиксируй допущение в отчёте. Если пробел меняет продукт или критерии, не угадывай: опиши конфликт и остановись.

## Что считать завершением

Только зелёные Docker-проверки, доказательства критериев и чистый итоговый diff. Формулировка «реализовано» без теста не считается доказательством.
