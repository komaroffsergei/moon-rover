# Время, победа и поражение

```text
1 реальная секунда = 1 игровая минута
60 реальных секунд = 1 игровой час
480 реальных секунд = 8 игровых часов
```

Симуляция обновляется fixed step 100 мс. UI может рисоваться через `requestAnimationFrame`, но не определяет время. Пауза прекращает вызовы `advance`.

## Recovery

При `resource > 0 → 0`:

1. статус центра `RECOVERY`;
2. `recoveryRemainingGameMinutes = 30`;
3. сообщение рации;
4. таймер уменьшается clock;
5. все ресурсы `>0` — `WORKING`, таймер сброшен;
6. таймер `0` — `DEFEAT`.

## Сообщения recovery

- 30: «Ресурс исчерпан. Центр на аварийном питании. До отказа 30 минут.»
- 20: «Осталось 20 минут. Требуется немедленная поставка.»
- 10: «Осталось 10 минут. Системы жизнеобеспечения отключаются.»
- 5: «SOS. Пять минут до потери центра.»
- 1: «Последняя минута. Повторяем: последняя минута.»
- восстановлен: «Поставка получена. Центр возвращён в рабочий режим.»
- 0: «Связь потеряна. Миссия провалена.»

Каждый порог создаётся один раз.

## Проверка конца смены

Порядок исхода однозначен:

1. `LOST` в любой момент немедленно завершает смену поражением.
2. Когда часы достигают конца смены, проверить все центры.
3. Победа только если каждый центр имеет статус `WORKING` или `WARNING`, то есть все три ресурса строго больше 0.
4. `RECOVERY` на момент окончания смены считается поражением, даже если его 30-минутный таймер ещё не истёк: центр не находится в рабочем состоянии.
5. Положение и состояние роверов не участвуют в условии победы.

Эта проверка выполняется внутри одного fixed-step после обновления ресурсов и доставок. При доставке и окончании смены на одном шаге сначала применяется подтверждённая доставка, затем вычисляется исход.
