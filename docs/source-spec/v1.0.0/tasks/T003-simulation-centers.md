# T003. Часы, центры, ресурсы и исход смены

**Feature spec:** `features/F003-simulation-centers.md`  
**Зависит от:** T002

## Цель

Реализовать чистую детерминированную симуляцию времени и научных центров без Phaser и React.

## Контекст задачи

Открыть только перечисленные файлы и уже созданный код, непосредственно связанный с задачей:

- `features/F003-simulation-centers.md`
- `specs/gameplay/02-clock-and-outcomes.md`
- `specs/gameplay/03-centers-resources.md`
- `specs/gameplay/10-state-model.md`
- `specs/technical/04-simulation.md`
- `contracts/balance.schema.json`

Не читать весь пакет «на всякий случай». Если нужное правило отсутствует, применить порядок приоритетов из `README.md`.

## В scope

- fixed step 100 ms;
- 8 минут реального времени = 8 игровых часов;
- постоянный расход кислорода и пайков;
- дискретный запрос оборудования;
- пороговые уведомления;
- 30 игровых минут восстановления;
- победа и поражение;

## Ожидаемые результаты

- `src/simulation/clock/*`;
- `src/simulation/centers/*`;
- `src/simulation/outcomes/*`;
- `детерминированные unit-тесты`;

Конкретные имена внутренних файлов можно скорректировать, если сохраняются границы ответственности и это объяснено в отчёте.

## Критерии приёмки

- [ ] пауза полностью останавливает sim time;
- [ ] пороговое сообщение не дублируется;
- [ ] ресурс 0 не вызывает мгновенное поражение;
- [ ] доставка в recovery window восстанавливает центр;
- [ ] поражение наступает ровно после 30 игровых минут;
- [ ] победа проверяет только состояние центров к концу смены;

## Не входит

- роверы;
- маршруты;
- рендеринг;
- реальная озвучка;

## Обязательный рабочий цикл

1. До изменений записать план максимум из 8 пунктов.
2. Найти самый маленький законченный вертикальный срез задачи.
3. Сначала добавить/уточнить проверяемые тесты или валидаторы требования.
4. Реализовать минимальный код, необходимый для прохождения этих проверок.
5. Запустить команды через Docker из `quality/THREE_PASS_WORKFLOW.md`.
6. Просмотреть итоговый diff и удалить код, не нужный этой задаче.
7. Создать `reports/T003.md` по `quality/REPORT_TEMPLATE.md`.

## Запрет завершения

Задача не считается выполненной по фразе «должно работать». В отчёте нужны фактические команды, их результат и ссылки на тесты, доказывающие каждый критерий.
