# T011. Четыре карты, баланс и ассеты

**Feature spec:** `features/F011-four-levels.md`  
**Зависит от:** T010

## Цель

Подготовить четыре различающиеся, валидные и проходимые карты с осмысленным выбором риска.

## Контекст задачи

Открыть только перечисленные файлы и уже созданный код, непосредственно связанный с задачей:

- `features/F011-four-levels.md`
- `specs/gameplay/09-levels-balance.md`
- `specs/technical/06-map-validation.md`
- `specs/technical/10-assets-tiles.md`
- `contracts/examples/`
- `references/04-map-risk-topology.png`

Не читать весь пакет «на всякий случай». Если нужное правило отсутствует, применить порядок приоритетов из `README.md`.

## В scope

- 4 Tiled JSON уровня;
- метаданные выбора;
- лёгкие локальные фоны WebP;
- крупные связанные danger zones;
- короткие рискованные и длинные безопасные варианты;
- нарастающая сложность;
- лицензионный реестр;

## Ожидаемые результаты

- `src/content/levels/*`;
- `public/assets/maps/*`;
- `public/assets/ui/* при необходимости`;
- `THIRD_PARTY_NOTICES.md`;
- `контент-тесты и balance smoke tests`;

Конкретные имена внутренних файлов можно скорректировать, если сохраняются границы ответственности и это объяснено в отчёте.

## Критерии приёмки

- [ ] каждый центр достижим;
- [ ] для заданной доли центров есть минимум два топологически разных пути;
- [ ] рискованный путь существенно короче безопасного по правилам уровня;
- [ ] опасные зоны не являются декоративными пятнами;
- [ ] все уровни можно выиграть в фиксированных smoke-сценариях;
- [ ] бюджет ассетов соблюдён;

## Не входит

- процедурная генерация;
- динамическая загрузка NASA-тайлов;
- платные ассеты;
- пятый уровень;

## Обязательный рабочий цикл

1. До изменений записать план максимум из 8 пунктов.
2. Найти самый маленький законченный вертикальный срез задачи.
3. Сначала добавить/уточнить проверяемые тесты или валидаторы требования.
4. Реализовать минимальный код, необходимый для прохождения этих проверок.
5. Запустить команды через Docker из `quality/THREE_PASS_WORKFLOW.md`.
6. Просмотреть итоговый diff и удалить код, не нужный этой задаче.
7. Создать `reports/T011.md` по `quality/REPORT_TEMPLATE.md`.

## Запрет завершения

Задача не считается выполненной по фразе «должно работать». В отчёте нужны фактические команды, их результат и ссылки на тесты, доказывающие каждый критерий.
