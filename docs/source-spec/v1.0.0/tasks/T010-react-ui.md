# T010. Компактный интерфейс диспетчера

**Feature spec:** `features/F010-react-ui.md`  
**Зависит от:** T009

## Цель

Собрать все игровые экраны и боковые панели вокруг карты без перегрузки интерфейса.

## Контекст задачи

Открыть только перечисленные файлы и уже созданный код, непосредственно связанный с задачей:

- `features/F010-react-ui.md`
- `specs/ui/01-screen-map.md`
- `specs/ui/02-main-layout.md`
- `specs/ui/03-interaction-states.md`
- `specs/ui/04-visual-style.md`
- `specs/ui/05-accessibility.md`

Не читать весь пакет «на всякий случай». Если нужное правило отсутствует, применить порядок приоритетов из `README.md`.

## В scope

- выбор уровня и briefing;
- основной HUD;
- левая сводка центров;
- правая выбранная сущность + действия;
- рация;
- route mode;
- center recovery state;
- rescue/transfer confirmation;
- pause, victory, defeat;

## Ожидаемые результаты

- `src/ui/screens/*`;
- `src/ui/panels/*`;
- `src/ui/components/*`;
- `src/store/gameStore.ts`;
- `Playwright smoke flows`;

Конкретные имена внутренних файлов можно скорректировать, если сохраняются границы ответственности и это объяснено в отчёте.

## Критерии приёмки

- [ ] на 1280x720 карта не меньше 65% полезной ширины;
- [ ] прогресс-бары центра видны над объектом и в панели;
- [ ] клавиатурный focus видим;
- [ ] критическое состояние не кодируется только цветом;
- [ ] модальные окна используются только для паузы, подтверждения батареи и финала;
- [ ] UI отправляет команды и не меняет сущности напрямую;

## Не входит

- mobile-first;
- UI-фреймворк;
- анимационная дизайн-система;
- чат;

## Обязательный рабочий цикл

1. До изменений записать план максимум из 8 пунктов.
2. Найти самый маленький законченный вертикальный срез задачи.
3. Сначала добавить/уточнить проверяемые тесты или валидаторы требования.
4. Реализовать минимальный код, необходимый для прохождения этих проверок.
5. Запустить команды через Docker из `quality/THREE_PASS_WORKFLOW.md`.
6. Просмотреть итоговый diff и удалить код, не нужный этой задаче.
7. Создать `reports/T010.md` по `quality/REPORT_TEMPLATE.md`.

## Запрет завершения

Задача не считается выполненной по фразе «должно работать». В отчёте нужны фактические команды, их результат и ссылки на тесты, доказывающие каждый критерий.
