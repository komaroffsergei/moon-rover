# Закрытие пробелов без раздувания scope

## Порядок

1. Найти ответ в `specs/product/03-decisions.md`.
2. Проверить feature-spec и соответствующий gameplay/technical документ.
3. Проверить `specs/product/04-assumptions.md`.
4. Только после этого классифицировать пробел.

## Мелкий пробел

Codex может принять минимальное решение без остановки, если оно одновременно:

- не создаёт новую пользовательскую функцию;
- не требует production-зависимости;
- не вводит новое долгоживущее состояние;
- детерминировано;
- обратимо;
- покрывается существующим критерием/тестом;
- не меняет победу, поражение, баланс или UI-flow.

Решение записать в отчёте как `локальное допущение`, не переписывая продуктовую спецификацию задним числом.

## Существенный пробел

Остановить реализацию и оформить конфликт, если решение меняет:

- scope или видимый геймплей;
- контракты между модулями;
- условие победы/поражения;
- форматы сохранённого контента;
- список зависимостей;
- бюджет/лицензию ассетов;
- последовательность задач.

## Запрещённая реакция

Не добавлять универсальную настройку, feature flag, интерфейс или плагин «чтобы поддержать оба варианта». Пока вариант один, код реализует один вариант.
