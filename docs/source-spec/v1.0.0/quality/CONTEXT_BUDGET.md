# Бюджет контекста Codex

## Основной режим

- Одна задача — один новый сеанс.
- Загружать только task prompt, перечисленные в нём 4–12 коротких документов и непосредственно изменяемый код.
- Не читать все feature/spec/task файлы «для уверенности». Это не уверенность, а дорогой способ смешать требования.
- Визуальные PNG открывать только для T009–T011 или точечного UI-review.
- После задачи сохранять короткий `reports/Txxx.md`; следующий сеанс читает отчёт, а не историю предыдущего диалога.

## Ответ Codex до кода

Максимум:

1. цель — 2–4 строки;
2. spec-audit — только найденные риски/пробелы;
3. план — до 8 пунктов;
4. список предполагаемых файлов;
5. команды проверки.

Не пересказывать спецификацию целиком.

## Ответ после кода

- перечислить изменённые зоны, не вставляя полный код;
- привести фактические команды и статусы;
- дать `requirement → evidence`;
- записать только новые допущения/ограничения;
- не дублировать содержимое README и CODEMAP.

## Работа с логами

Сначала читать конец ошибки и целевой stack trace. Полные логи сохранять файлом при необходимости; в контекст переносить только релевантный фрагмент. После исправления повторить минимальную проверку, затем полный gate один раз.

## Reasoning

- `high`/Plan mode: T001, T002, T009–T012 или реальный конфликт спецификаций.
- `medium`: изолированные T003–T008 после spec-audit.
- Не повышать reasoning ради механического форматирования или повторного запуска зелёной команды.
