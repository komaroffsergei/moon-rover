# AGENTS.md

## Рабочий режим

1. Открыть одну задачу из `tasks/` и только указанный ею контекст.
2. До кода перечислить цель, затрагиваемые файлы, риски и проверки.
3. Не реализовывать следующую задачу и не расширять scope.
4. После реализации выполнить три прохода из `quality/THREE_PASS_WORKFLOW.md`.
5. Создать `reports/Txxx.md` по шаблону.
6. Не объявлять завершение, пока критерии и Docker-проверки не выполнены.

## Источник истины

- Для неизвестного поведения применять `quality/GAP_HANDLING.md`.
- Для экономии контекста применять `quality/CONTEXT_BUDGET.md`.

- Приоритет документов находится в `README.md`.
- Визуальные референсы не задают игровые числа.
- При мелком пробеле выбрать минимальное поведение без новой функции и записать допущение в отчёт.
- При существенном конфликте остановиться и описать его. Не угадывать желание владельца продукта.

## Границы модулей

Полный разрешённый граф импортов: `specs/technical/13-module-boundaries.md`.

- `src/simulation` — чистая TypeScript-логика и единственный источник истины.
- `src/game` — Phaser: карта, камера, отображение, преобразование ввода в команды.
- `src/ui` — React: экраны, панели, рация, подтверждения.
- `src/content` — Tiled/JSON, баланс, события, сообщения, темы.
- `src/shared` — только реально общие небольшие функции.
- Simulation не импортирует React, Phaser, Zustand, DOM и browser timers.
- React и Phaser не меняют игровые сущности напрямую.

## Простота

- Не создавать абстракцию до двух реальных применений.
- Предпочитать функции и композицию наследованию.
- Ориентир обычного файла — до 250 строк и одна ответственность. Не дробить последовательный алгоритм ради числа.
- Не создавать `Manager`, `Service`, `Factory`, `Provider`, если это маскирует простую функцию.
- Запрещены ECS, DI-контейнер, CQRS, Redux, XState и сторонняя event bus.
- Запрещены `any`, прямой `Math.random()` и `setTimeout()` для игровой логики.
- Все коэффициенты хранятся в валидируемом контенте.
- Комментарии/JSDoc на русском объясняют правило или причину.

## Зависимости

- Разрешены только пакеты из `specs/technical/09-dependencies.md`.
- Новая production-зависимость сначала оформляется решением в `specs/product/03-decisions.md`.
- Не использовать runtime CDN.
- Lockfile обязателен; массовое обновление пакетов запрещено.

## Docker

- Dev, lint, typecheck, test, content validation, build и E2E запускаются через Docker Compose.
- Production — multi-stage image со статической сборкой в nginx.
- Версия Playwright image совпадает с `@playwright/test`.

## Игровые запреты

- MapLibre не использовать.
- Игрок выбирает ровер и правым кликом задаёт цель; runtime строит риск-взвешенный путь.
- Роверы не обязаны вернуться для победы.
- Запасы базы не ограничены.
- Несколько роверов могут быть в одной клетке; столкновений нет.
- Ресурс 0 запускает 30 игровых минут восстановления, а не мгновенное поражение.
- Нет ручного вождения и физики.

## Проверки ревью

Считать дефектом:

- нарушение границы модулей;
- игровую логику в компоненте/сцене;
- баланс в коде;
- недетерминированность;
- невалидируемый JSON;
- зависимость без решения;
- абстракцию без двух применений;
- тест, который не доказывает требование;
- изменение вне текущей задачи.
