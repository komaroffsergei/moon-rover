# Стиль кода

## Главный критерий

Код должен читаться сверху вниз без знания внутренней мифологии проекта. Простая функция предпочтительнее абстрактной платформы, созданной ради единственного вызова.

## TypeScript

- `strict: true`, `noUncheckedIndexedAccess: true`, `exactOptionalPropertyTypes: true`.
- `any` запрещён; на границе неизвестного ввода использовать `unknown` и Zod.
- Доменные ID — читаемые строки, не UUID.
- Состояния моделировать discriminated union, а не набором независимых boolean.
- Денормализованные вычисляемые значения не хранить без доказанной причины.
- Мутация допустима только внутри закрытой функции редьюсера/шага симуляции, снаружи отдаётся snapshot.

## Файлы и функции

- Один файл — одна ответственность; ориентир 40–250 строк.
- Не дробить один последовательный алгоритм на десяток файлов ради формального лимита.
- Функция обычно до 40 строк; длиннее допустима, если это единый прозрачный алгоритм.
- Абстракция появляется не раньше двух реальных применений и только если уменьшает код.
- Не использовать суффиксы `Manager`, `Service`, `Factory`, `Provider` без конкретной необходимости.
- Избегать barrel-файлов; импортировать из явного модуля.

## Имена

- Доменные термины совпадают с `specs/product/02-glossary.md`.
- Команды — глагол + объект: `confirmRoute`, `dispatchRover`, `transferBattery`.
- Boolean — `is/has/can/should`.
- Единицы в имени: `gameMinutes`, `realMs`, `batteryUnits`.

## Комментарии

- Комментарии и JSDoc на русском.
- Объясняют правило, ограничение или причину, а не переводят синтаксис.
- Сложный алгоритм сопровождается коротким примером входа/выхода.
- TODO запрещён без ссылки на текущую задачу; TODO будущего scope не оставлять.

## Ошибки

- На внешней границе возвращать понятный список ошибок с путём поля.
- Внутренний невозможный state подтверждать `assertNever`.
- Не скрывать исключение пустым `catch`.
